# ComplexityResearch

Учебное WPF-приложение (C#, .NET 9) для **эмпирического анализа временной
сложности алгоритмов**: измеряет фактическое время выполнения, сравнивает его
с теоретической моделью T(n) = Σ countᵢ·costᵢ, строит аппроксимацию
Tapprox(n) = C·f(n) с оценкой качества MSE, хранит результаты в SQLite с кэшем
и включает операционный бенчмарк возведения в степень (подсчёт элементарных
операций). Проект в разработке.

## Возможности

- **Алгоритмы временного бенчмарка (№1–№9):**
  константа O(1); сумма O(n); произведение O(n) (модульная арифметика);
  многочлен наивно O(n²); метод Горнера O(n);
  возведение в степень итеративно O(n) / рекурсивно O(n) / бинарно O(log n);
  Bubble Sort O(n²); Quick Sort O(n log n) average / O(n²) worst (собственная
  реализация, медиана трёх); TimSort O(n log n) (собственная реализация);
  умножение матриц O(n³).
  Кастомные (индивидуальные) алгоритмы №10–№12 — в разработке.
- **Benchmark:** Nmax + step, 5 запусков по умолчанию (+ прогревочные), Seed,
  лимит времени точки, измеряется только выполнение алгоритма (данные,
  память, БД, GUI — вне таймера), `Stopwatch`, прогрев JIT.
- **БД и кэш:** SQLite; отдельные запуски построчно (Algorithm, n, RunNumber,
  ElapsedTime, StepCount, ExperimentDate) + параметры эксперимента и
  теоретическое значение; ключ кэша = алгоритм + n + параметры;
  «Use cache» / «Force recalculation».
- **Аппроксимация и MSE:** Tapprox(n) = C·f(n) (МНК), MSE = (1/k)Σ(T_эмп−Tapprox)²
  — в GUI, в таблице, в экспорте и в БД.
- **Графики:** эксперимент + теоретическая модель + аппроксимация, MSE
  в заголовке; обычная/логарифмическая шкала, зум/пан, экспорт PNG;
  график «операции vs n» для возведения в степень.
- **GUI:** выбор алгоритма, Nmax, step, запусков, Seed, кэш, запуск/остановка,
  принудительный пересчёт, таблица, график, прогресс; UI не блокируется.
- **Тесты:** xunit — алгоритмы, сортировки, многочлены, матрицы, степени,
  счётчик операций, аппроксимация, MSE, БД/кэш, конфигурации, интеграция.

## Сборка, запуск, тесты

Требуется .NET SDK 9 и Windows.

```bash
dotnet build -c Release
dotnet run -c Release --project ComplexityResearch
dotnet test ..\ComplexityResearch.Tests -c Release
```

Или откройте `ComplexityResearch.sln` в Visual Studio 2022, конфигурация
**Release**, F5.

> **Важно:** измерения корректны только в Release. В Debug JIT не оптимизирует
> код, и результаты искажаются в несколько раз.

## Прямой и масштабированный режимы

Для линейных алгоритмов при n > 50 000 000 массив размером n не выделяется:
обрабатывается блок 50 млн элементов с числом проходов, пропорциональным n
(пометка «Масштабированный» в таблице и отчёте). Сортировки всегда прямые.

## Добавление нового алгоритма

1. Класс-наследник `AlgorithmBase` (или `IOperationCountedAlgorithm`).
2. Реализация обязательных членов (имя, сложность, конфигурация, данные,
   ядро, счётчик операций).
3. Одна строка в `AlgorithmRegistry`.

Сервисы, график, таблица, БД и экспорт менять не нужно.
